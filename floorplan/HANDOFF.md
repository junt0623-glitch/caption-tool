# 展覧会図面作成アプリ — 引き継ぎメモ

## 現状
`index.html` 単一ファイルの展覧会平面図エディタ(SVGベース、外部依存なし)。
チャットのClaudeが破損ファイルから再構築し、レイヤー・在庫・作品リスト連携まで拡張した版。

## レイヤー構成(描画順)
1. **最背面: 展示室図面** — 4面をデフォルト登録(展示室1-A（旧第1）/1-A（旧第2）/1-B/2-B)。
   何も選択していないときの右パネルで選択し、図面画像(PNG/JPG。PDFは要変換)を
   読み込み・倍率/位置/透明度を調整。A3の範囲内に最大サイズで自動フィット。
   画像は必ず compressRoomImage()(長辺3000px・JPEG品質0.85に圧縮)を経由してから
   state.rooms.list[].img に dataURL で保存し、JSON保存に含まれる。
   **圧縮を経由させること自体が重要**: render() はドラッグやスライダー操作のたびに
   SVGを総入れ替えするため、生の(圧縮していない)dataURLを使うと巨大な画像が
   毎フレーム再デコードされてタブがフリーズする(過去に実際に起きた不具合。
   tests/fp04_large_image_no_freeze.js が回帰テスト)。
   回転は**個別に持たず、印刷範囲(state.sheet.rot)と共通の1つの値**を使う
   (「印刷範囲と図面を個別に回転させない」という要件。詳しくは後述の
   「印刷範囲(A3)の回転」の項を参照)
2. 壁
3. **ケース・展示台(在庫方式)** — 印刷範囲の外に種類ごと1つのパレットを表示。
   可動ケース10種(α×2, β×3, 180角×4, 横長免震×3, 横長免震背景×3,
   横長非免震×2, 横長非免震背景×3, 行燈免震×5, 行燈非免震×1, のぞき×5)は左側に縦一列、
   展示台5種(1.53×0.9×27, 1.8×0.9×24, 0.9×0.9×7, 2.0×2.0×2, 1.2×0.9×30)は右側に縦一列。
   パレットをクリック/ドラッグすると1台取り出せて残数が減り、削除すると残数に戻る。
   パレットには種類名・`使用 N`(この図面での使用台数)・`残 N / 総数` の3行を表示する
   (それぞれ `.stock-name` / `.stock-used` / `.stock-remain` クラス。テストがこの
   クラス名でテキストを拾うので、表示順を変えるときはクラスごと動かすこと)。
   残数 = total − この図面での使用数 − 他の図面での使用数 で常に導出(同期バグ防止)。
   `stockDef()` / `stockUsed()` / `stockElsewhere()` / `stockRemain()` に集約してあるので、
   残数を数える処理を他所に書き足さないこと。
   **在庫の総数(total)はアプリ側の設定であり、ファイルに保存された値を信用しない**:
   JSON読み込み時は `state.stock = defaultStock();` で無条件に上書きする
   (`if (!state.stock) ...` のような「無ければ補う」書き方はNG。過去に、
   総数を18→27台に変更しても古い保存ファイルを開くと18台のままになる
   不具合があった。stockKeyだけ見て残数を数え直す設計なので、総数を
   まるごと上書きしても配置済みオブジェクトのデータは壊れない。
   tests/fp07_stock_refreshes_on_load.js が回帰テスト)

   **他の展示室(別の図面)での使用台数** — 同じ備品を複数の展示室で取り合うため、
   ヘッダーの「📦 在庫」パネルで種類ごとに「他の図面」の台数を入力できる。
   値は `state.usedElsewhere = {stockKey: 台数}` に持ち、保存JSONにも含まれる
   (総数と違い、これは利用者が入力したデータなので読み込み時に上書きしない。
   古いファイル対策として、オブジェクトでなければ `{}` に初期化するだけ)。
   入力があるとパレットの表示は `使用 2 (他 1)` のように併記になる。
   合計を超えて割り当てると残数がマイナスになり、パネル下部に不足種類の警告が出る。
   マイナスの間はパレットからの取り出しを禁止する(残数チェックは `remain > 0`)。

   **背景つきケース(横長免震背景・横長非免震背景)** — 在庫定義の `back:true` で表し、
   `drawBackEdge()` が長辺(幅の側)の1本を通常の3倍の太さの線で描く。
   パレットと配置済みオブジェクトの両方で描くこと(片方だけだと図面上で背景の向きが
   分からなくなる)。配置済み側は `isBackCase(o)` で判定する。
   tests/fp09_stock_panel.js が台数設定・太線・使用数表示・他図面ぶんの入力と
   保存/読み込みの回帰テスト。
4. **作品** — 図面上は「番号」バッジのみ表示(作品名等は出さない)。
   作品リストの番号に対応する画像があればそれを表示
5. **最前面: テキスト**

各レイヤーは右パネル上部のチェックボックスで表示/非表示を切替(ビュー状態、保存対象外)。
描画順は type から layerOf() で決まり、同レイヤー内は objects 配列順(安定ソート)。

## 作品リスト(CSV)と画像の連携
- ヘッダーの「📋 作品リスト」でCSV/TSVを読み込む(Excelから「CSV形式で保存」を想定)。
  「番号」列(なければ1列目)・「作品名」「作家名」列を自動判別。
  Shift_JIS/UTF-8両対応(UTF-8で化けたらShift_JISで再デコード)
- 作品ツールでの配置時、番号は `workQueue()` が返す並びの先頭から自動割り当て。番号は右パネルで変更可

## 作品を「任意の番号から順番に」配置する
- 配置に使う番号の並びは `workQueue()` が決める。**画像フォルダ(state.library)の番号**を
  小さい順に並べ、`state.workStartNo` 以上・未配置のものだけを返す。
  画像フォルダが空なら作品リストの番号で代用し、どちらも空なら従来どおりの連番になる
- 開始番号 `state.workStartNo` は右パネル(作品ツールのときだけ表示)で入力する。
  `normNo()` を通すので「Ｎｏ．１０００２」のような全角・接頭辞つきでも数字を拾う。
  図面ごとの設定なのでJSONに保存する(読み込み時、無ければ空文字で補う)
- **1つ置いたら必ず `setTool("select")` で選択ツールに戻す**。
  「番号が尽きるまで作品ツールのまま」にしたことがあるが、置いた作品を触ろうとした
  タップで次の作品が増えてしまい使いづらいと差し戻しになった(特にiPad)。
  連続で置きたいときは「作品」を押し直す。番号の並びは配置済みを飛ばすので、
  押し直しても続きから置ける
- **配置時に imgId は結びつけない**。画像は `workImage()` の番号一致で出るので、
  あとから番号を直せば画像も追従する。imgIdを付けてしまうと追従しなくなる
- `setTool()` は最後に `renderSide()` を呼ぶ。呼ばないとツールを切り替えても
  右パネルに開始番号の欄が出ない
- tests/fp14_work_sequence.js が回帰テスト

## 画像フォルダ(作品画像)
- ヘッダーの「🗂 画像フォルダ」でモーダルを開き、**作品を配置する前に**画像を
  まとめてアップロードしておける。中身は `state.library` = `[{id,name,no,img}]` で
  **JSON保存にそのまま含まれる**(保存ファイルを開けば画像も一緒に復元される)
- 画像は必ず compressImage()(長辺512px・JPEG品質0.72)を通してから library に入れる
  (生のFileReader結果を直接stateに入れないこと。render()が毎回SVGを作り直すため
  フリーズの原因になる。展示室図面のcompressRoomImageも同様)
- ファイル名の数字(例: 10001.jpg)は normNo() で正規化して `it.no` に持ち、
  同じ番号の作品に**自動で対応**する(従来の一括読み込みと同じ使い勝手を維持)
- **図面上の作品をダブルクリック**すると選択モードでモーダルが開き、
  クリックした画像が `obj.imgId` に入る(右パネルの「🗂 画像フォルダから選ぶ」も同じ)
- 表示する画像の決定は必ず `workImage(o)` を通す。優先順位は
  `imgId`(明示選択) → `img`(旧形式の個別指定) → 番号一致 → `state.images`(旧形式)
- 旧形式JSON(番号→dataURLの `state.images` だけを持つファイル)は読み込み時に
  library へ移行する。`state.images` 自体は互換のため残してある
- **ダブルクリックはブラウザの dblclick イベントでは取れない**。render() が
  pointerdown のたびにSVGを総入れ替えするため、押した要素と離した要素が別物になり
  click/dblclick がそもそも発火しない(実際に踏んだ)。pointerdown 内で
  `lastTap`(直前に押したオブジェクトIDと時刻)を見て自前で二度押しを判定している。
  副次的にタッチのダブルタップにも対応できている
- 画像フォルダの中身(library)は履歴スナップショットから除外している。一方で
  作品への割り当て `obj.imgId` は短い文字列なので通常どおりUndo/Redoできる
- 番号の照合は normNo()(全角→半角、数字抽出、先頭ゼロ除去)で統一すること
- tests/fp08_image_library.js が一連の流れ(事前アップロード→ダブルクリック選択→
  保存→読み込みで復元)の回帰テスト

## ポインタ操作(タッチ対応の注意点)
- **pointerdownはsvg、pointermove/up/cancelはwindowで受ける**。
  「押し始めは図面の上、その後は画面のどこでも追いかける」という形にすることで、
  ポインタ捕捉(setPointerCapture)が効かない環境でも動く。
  move/up/cancelをsvgだけで受けてはいけない: 指を図面の外に出したときや
  捕捉に失敗したときにupがsvgに届かず、`pointers` Mapに古い指が残る。
  残ると次のタッチが「2本目の指(ピンチ)」と誤判定され、
  **以後どこを触っても無反応になる**(再読み込みするまで直らない)
- **`svg.setPointerCapture()` は必ず try/catch で囲む**。iOS Safariでは例外を
  投げることがあり、pointerdownの先頭で落ちると選択・移動・在庫からの取り出しが
  まるごと実行されない。これも「タッチしても反応しない」に見える
- 指の後始末は `releasePointer()` に一本化する。タブを離れたとき(blur/visibilitychange)も
  `pointers` を空にする(upが届かないまま戻ってくることがあるため)
- CSSは `touch-action:none` だけでは足りない。iOS Safariは長押しの選択・コピーメニューや
  ダブルタップ拡大で指を横取りする(pointercancelになる)ので、
  `-webkit-user-select:none` / `-webkit-touch-callout:none` /
  `-webkit-tap-highlight-color:transparent` も指定する
- tests/fp13_touch_ipad.js が回帰テスト。この環境ではWebKitを動かせないため、
  Chromiumのタッチ操作に加えて `setPointerCapture` を例外を投げる実装に差し替え、
  iOS Safariで起きる状況を作って検証している

## 選択・移動・整列
- 単一選択: クリック。ドラッグで移動(既定50mm刻み=FINE、**Altキーでスナップ無し=1mm自由**)
- 複数選択: Shift/Ctrl/Cmd+クリックでトグル追加、空白を Shift+ドラッグで範囲選択(マーキー、
  中心が矩形内のオブジェクトを追加選択)、Ctrl/Cmd+A で全オブジェクト選択
- 複数選択中はオブジェクトをドラッグするとグループごと移動(主選択を基準にスナップ)
- **壁もオブジェクトと同様にドラッグ移動できる**(始点・終点をまとめて平行移動)。
  壁は state.objects ではなく state.walls にいる別の配列なので、pointerdown の
  ドラッグ対象を組み立てるループは objects・walls の両方を見ること。
  片方だけ見て primary/items を作ると「選択はできるが動かない」不具合になる
  (実際に起きた回帰。tests/fp01_floorplan_smoke.js の壁ドラッグテストで検知)
- **整列ツール**(2個以上選択で右パネルに表示): 左/右/左右中央、上/下/上下中央そろえ、
  横/縦の等間隔配置(disth/distv)。基準は選択全体のバウンディング(壁は対象外、
  state.objects のみ)。当たり判定・整列の寸法は halfExtent()(縮尺fを考慮)で算出
- **複数選択での回転**(同じく2個以上選択で表示): ↺90°/↻90°/↺15°/↻15°ボタン。
  rotateSelected() が state.objects のうち選択中のものすべての obj.rot に
  同じ角度を加算する(0〜359に正規化)。整列と違い「1つの軸を中心に集団で回す」
  のではなく、各オブジェクトの位置(x,y)はそのまま・向きだけを個別にずらす仕様
  (バラバラな向きで置いたケース・展示台をまとめて直したい、という用途を想定)
- 選択状態(selectedIds:Set / selectedId:主選択)は保存対象外。履歴のUndoでクリアされる

## 主な機能
- 壁の描画(ドラッグ、直交スナップ / Shiftで自由角度)
- 壁の連結(既存の壁の端点400mm以内に近づけると吸着。連結時は直交スナップより優先)
- **壁のコピー&ペースト**(Ctrl+C / Ctrl+V、または選択中パネルのコピーボタン)。
  対象は壁のみ(作品・ケース・展示台・テキストは非対応。ケース/展示台は
  在庫が有限なのでコピーで台数を増やせてしまうと矛盾するため、あえて対象外にした)。
  `wallClipboard`(コピーした壁の x1,y1,x2,y2 をそのまま保持)と、
  貼り付けるたびに重ならないよう少しずらす `pasteCount` を持つグローバル変数。
  貼り付けごとに PASTE_OFFSET(500mm)×貼り付け回数だけx,y両方にオフセットを
  加える(階段状にずれていく一般的なコピペUIと同じ挙動)。コピーし直すと
  pasteCount は0にリセットされる。貼り付け後は貼り付けた壁が選択状態になる
- Ctrl+Zで元に戻す / Ctrl+Y・Ctrl+Shift+Zでやり直し(履歴50件)。
  ※画像(state.images / rooms.img / objects.img)は履歴スナップショットから除外し、
  Undo/Redoをまたいで現在値を維持する(メモリ対策。snapshot()/applySnapshot()参照)
- タッチ2本指のピンチズーム・パン
- **印刷範囲(A3)は90度きざみで回転でき、展示室図面・壁・作品・ケース・展示台・
  テキストなど配置済みのもの全てがこれと連動して一緒に回転する**
  (state.sheet.rot: 0/90/180/270、既定0。ヘッダーの「印刷範囲(A3)の回転」で切替。
  normRot()で0/90/180/270に丸める)。
  0°/180°はSHEETが横向き(42000×29700mm)、90°/270°は縦向き(29700×42000mm)。
  展示室図面と印刷範囲を個別に回転させると縦横比がズレて対応しなくなるため、
  回転は共通の値ひとつだけにし、図面側に専用の回転設定は持たせていない。
  図面の描画は BASE_SHEET_W/H(=常にA3横基準、42000×29700)で箱のサイズを固定し、
  SHEETと同じ角度・SHEETの中心(SHEET.w/2, SHEET.h/2)を軸に rotate() するだけで、
  回転後の見た目のバウンディングボックスが常にSHEETの寸法・位置と一致する
  (箱を90°回転すると42000×29700→29700×42000になり、SHEET(90°)の29700×42000と
  ちょうど揃う、という関係を利用している。dx/dyはこの自動センタリングからの
  ずれとして加算する。tests/fp02_floorplan_layers.js で回転後の4隅がSHEETの
  範囲にちょうど一致することを行列計算で検証している)
- **壁・作品・ケース・展示台・テキストは、印刷範囲の回転が変わった瞬間に
  座標そのものを新しい回転後のフレームへ焼き込む(bake)方式**で回転に対応する
  (展示室図面のような「毎フレーム回転transformをかけ続ける」方式とは違う実装)。
  sheetSel の onchange で `rotateContentWithSheet(fromRot, toRot)` を呼び、
  state.walls / state.objects の座標を1回だけ書き換えてから state.sheet.rot を
  更新する。この方式にした理由: ドラッグ・スナップ・整列・マーキー選択など
  既存の操作コードは「obj.x/y は常に“今のSHEET”の座標系そのもの」という前提で
  書かれているため、もし表示側だけ回転させる(部品を包む`<g>`にrotateを常時
  かける)方式にすると、pointerdown/pointermove/marquee/snapWallPoint/halfExtent
  などクリック位置や当たり判定を扱うコードすべてに逆回転変換を入れる必要が
  出て影響範囲が非常に大きくなる。座標を焼き込む方式なら、回転が変わった
  その瞬間だけ変換すればよく、それ以外のコードは一切変更不要で済む
  - `remapPointForRotation(x,y,fromRot,toRot)`: 「今の回転でのフレーム座標」→
    「常にA3横基準の物理座標」(BASE_SHEET_W/Hを介する。展示室図面のrotate()と
    同じ考え方)→「新しい回転でのフレーム座標」の順で変換する
  - `cosDeg()/sinDeg()`: 0/90/180/270度に限定した厳密な三角関数(Math.cos/sinの
    浮動小数誤差で90°×4回転させても元にぴったり戻らない、という事態を防ぐ)
  - 壁は始点・終点をそれぞれ remapPointForRotation するだけで向き・長さが
    自動的に保たれる(壁専用のrot値は持たない)
  - オブジェクトは位置に加えて obj.rot にも回転量(delta)を加算する。
    **ここで normRot()(90度に丸める関数)を使わないこと** — obj.rotは
    15度刻み等の任意角度を取りうるので、丸めると値が壊れる(実際にあった
    バグ)。単純な `((v%360)+360)%360` で正規化すること
  - 展示室図面(state.rooms.list[].img)は対象外(既にstate.sheet.rotを直接
    参照して毎回描画時に回転しているので、二重に回さないよう除外している)
  - tests/fp05_content_rotates_with_sheet.js で「壁・ケース・作品の位置と向きが
    期待どおりに変換されること」「90°×4回転(1周)しても浮動小数の誤差で
    ずれずちょうど元に戻ること」「Undoで1手ずつ正しく戻ること」を検証している
- **縮尺(0〜150%)**: ケース・展示台の図面に対する表示サイズ倍率(state.scalePct)。
  背景図面の縮尺が不明でも、この%を調整してケースと図面の大きさを合わせる。
  実寸mm(o.w/o.h)は変えず描画時に dispSize()/fsc() を掛けるだけ。
  0%近くでも掴めなくならないよう表示サイズはMIN_DISP(120mm)を下限に保証する
  (halfExtent()・在庫パレット・配置済みオブジェクトすべてdispSize()経由で統一)。
  scalePctは0が正当な値なので `!state.scalePct` のようなfalsy判定は禁止
  (0が100にフォールバックされてしまう。== null で判定すること。過去にこのバグがあった)
- 表題欄は廃止(図面上に展覧会名等は表示しない。state.metaはファイル名用に残存)
- 保存ファイル名は `<展覧会名>_<保存日>.json`。**保存日(state.meta.date)は保存ボタンを
  押した時点で today() に更新する**。初期化時に一度入れるだけだと、図面JSONを読み込んだ
  ときに保存ファイル側の古い日付で上書きされ、保存し直してもファイル名の日付が
  更新されない不具合になる(tests/fp10_save_filename_date.js が回帰テスト)
- JSON保存/読み込み(旧形式と互換)、PNG書き出し、印刷

## Googleドライブからの読み込み
- ヘッダーの「☁ ドライブ」でGoogle Pickerを開き、選んだファイルをDrive APIで
  取得して読み込む。JSONなら図面データ、CSV/TSV/TXTなら作品リストとして扱う
  (振り分けは `isWorkListName()`。拡張子とMIMEタイプの両方を見る)
- **取り込み処理はローカルファイルと共通**: `applyPlanText(text)` と
  `applyWorkListBlob(blob)` にまとめてあり、ファイル入力もドライブも同じ関数を通る。
  読み込みの仕様を変えるときは必ずこの2つを直すこと(片方だけ直すと経路で挙動がズレる)
- スコープは `drive.file` のみ。**Pickerで選んだファイルしか読めない**ので、
  ドライブ全体を見にいくことはない。広いスコープ(drive.readonly等)に変えないこと
- クライアントIDとAPIキーは利用者ごとに違うので、アプリには埋め込まず
  設定画面(`#driveModal`)で入力させ `localStorage["floorplan.driveConfig"]` に保存する。
  **アクセストークンは保存しない**(メモリ上の `driveToken` だけ。失敗時はnullに戻して取り直す)
- GoogleのJS(gsi/client, apis.google.com)は「☁ ドライブ」を押したときだけ
  `loadScriptOnce()` で読み込む。起動時に読むとオフラインや file:// で余計な失敗が出る
- **file:// では使えない**(OAuthの生成元がURLでないと成立しないため)。
  設定画面はその場合に案内を出す。GitHub Pagesのページから使うこと
- 設定ミス(IDの誤り・生成元の登録漏れ)が失敗原因の大半なので、
  失敗時はconfirmで設定画面を開き直せるようにしてある。
  設定済みでも Shift+クリック で設定画面を開ける
- tests/fp12_google_drive.js が回帰テスト。GoogleのJSと Drive API を
  page.route() で偽物に差し替え、認証〜選択〜取り込みの流れを検証している

## 印刷
- **印刷では印刷範囲(A3)だけが用紙いっぱいに出る**。仕組みは3つの組み合わせ:
  1. 印刷時のviewBoxは `0 0 SHEET.w SHEET.h`(印刷範囲そのもの)を直接セットする。
     **applyView()を使ってはいけない**: 画面の縦横比に合わせてviewBoxを左右(縦なら上下)に
     広げるため、印刷範囲の外に並べてある在庫パレットが用紙に写り込む
     (A3縦のときは左右に12000mm以上も広がっていた。これが実際の不具合)
  2. `<style id="pageStyle">` に `@page{size:A3 landscape|portrait;margin:0}` と
     `#canvasWrap` のmm実寸(420×297 / 297×420)を印刷ボタンを押した時点で差し込む。
     向きは SHEET.w/h から決めるので、印刷範囲を90/270度に回しても対応する。
     **`#canvasWrap` を `inset:0`(紙いっぱい)にしてはいけない**: プリンター側の
     用紙がA4のままだと図面もA4の大きさで出てしまう(実際に起きた不具合)。
     mm実寸で指定しておけば、用紙設定に関わらず常にA3の大きさで印刷される。
     `@page` の既定(A3横)は静的なCSSにも書いてあり、印刷プレビューを開いた
     時点で用紙がA3と分かるようにしている
  3. render()の描画物はすべて `g.sheet-root` にまとめ、@media printで
     `clip-path:url(#sheetClip)`(印刷範囲と同じ矩形)を掛ける。
     画面編集中はクリップしないので、印刷範囲の外にも自由に物を置ける
- 在庫パレット(`.stock`)は編集用UIなので @media print で display:none にする
- render()内で新しい要素を足すときは親を `svg` ではなく `root` にすること
  (`svg` 直下に足すとクリップの外になり、印刷範囲の外にはみ出しても切れずに印刷される)
- tests/fp11_print_area.js が回帰テスト

## 座標系・単位
- 内部座標はmm。SHEETはA3実寸(mm)×100(state.sheet.rotの0/90/180/270で横縦を切替。
  旧形式JSON(state.sheet.preset: "a3l"/"a3p"等)は読み込み時にrotへ変換する)
- グリッドは500mm、壁厚は固定150mm
- viewBoxで拡縮しているズーム/パン

## 既知の設計上の注意点(SVG特有)
- SVGはCSSがプレゼンテーション属性より優先される。font-size等はCSSクラスに書かず
  属性 or インラインstyleで指定すること(過去に文字が極小になるバグがあった)
- PNG書き出し時、外部<style>はcloneNode後にシリアライズされないため
  書き出し関数内でスタイルをSVGに埋め込んでいる(pngBtnのonclick内)
- render()は呼ばれるたびにsvg.innerHTMLを空にして全要素を再生成する(差分更新ではない)。
  ドラッグ中のpointermoveやスライダーのoninputで毎回呼ばれるため、
  <image>のhrefに巨大なdataURLを入れるとブラウザが毎フレーム再デコードしてフリーズする。
  画像を扱う新機能を足すときは必ずcompressImage()系を経由してdataURLを小さく保つこと
