# 展覧会図面作成アプリ — 引き継ぎメモ

## 現状
`index.html` 単一ファイルの展覧会平面図エディタ(SVGベース、外部依存なし)。
チャットのClaudeが破損ファイルから再構築し、レイヤー・在庫・作品リスト連携まで拡張した版。

## レイヤー構成(描画順)
1. **最背面: 展示室図面** — 4面をデフォルト登録(展示室1-A（旧第1）/1-A（旧第2）/1-B/2-B)。
   何も選択していないときの右パネルで選択し、図面画像(PNG/JPG。PDFは要変換)を
   読み込み・倍率/位置/透明度を調整。A3の範囲内に最大サイズで自動フィット。
   画像は必ず compressRoomImage()(長辺3000px・JPEG品質0.85に圧縮)を経由してから
   state.rooms.list[].img に dataURL で保存し、JSON保存に含まれる。
   **圧縮を経由させること自体が重要**: render() はドラッグやスライダー操作のたびに
   SVGを総入れ替えするため、生の(圧縮していない)dataURLを使うと巨大な画像が
   毎フレーム再デコードされてタブがフリーズする(過去に実際に起きた不具合。
   tests/fp04_large_image_no_freeze.js が回帰テスト)。
   スキャンが横向き/上下逆等のときは「画像の回転」で0/90/180/270度に補正できる
   (state.rooms.list[].rot。画像自身の中心(x+w/2, y+h/2)を軸にSVGの
   rotate()で回転。位置・倍率・透明度の設定値はそのまま活きる)
2. 壁
3. **ケース・展示台(在庫方式)** — 印刷範囲の外に種類ごと1つのパレットを表示。
   可動ケース9種(α×2, β×10, 180角×2, 横長免震×5, 横長免震背景×1,
   横長非免震×1, 横長非免震背景×2, 行燈免震×5, のぞき×5)は左側に縦一列、
   展示台5種(1.53×0.9×18, 1.8×0.9×12, 0.9×0.9×7, 2.0×2.0×2, 1.2×0.9×30)は右側に縦一列。
   パレットをクリック/ドラッグすると1台取り出せて残数が減り、削除すると残数に戻る。
   残数 = total −「stockKeyが一致する配置済みオブジェクト数」で常に導出(同期バグ防止)
4. **作品** — 図面上は「番号」バッジのみ表示(作品名等は出さない)。
   作品リストの番号に対応する画像があればそれを表示
5. **最前面: テキスト**

各レイヤーは右パネル上部のチェックボックスで表示/非表示を切替(ビュー状態、保存対象外)。
描画順は type から layerOf() で決まり、同レイヤー内は objects 配列順(安定ソート)。

## 作品リスト(CSV)と画像の連携
- ヘッダーの「📋 作品リスト」でCSV/TSVを読み込む(Excelから「CSV形式で保存」を想定)。
  「番号」列(なければ1列目)・「作品名」「作家名」列を自動判別。
  Shift_JIS/UTF-8両対応(UTF-8で化けたらShift_JISで再デコード)
- 作品ツールでの配置時、リストの未配置の先頭番号を自動割り当て。番号は右パネルで変更可
- 「🖼 作品画像」で画像を一括読み込み。ファイル名の数字(例: 10001.jpg)を
  normNo() で正規化してリストの「番号」と対応付ける。
  長辺512px・JPEG品質0.72に圧縮して state.images[番号] に保存(JSON保存に含む)
- 作品ごとの個別画像(右パネルの「画像を選択」)も同じ compressImage() を経由する
  (既定は長辺512px・品質0.72。roomFile/pImgFileどちらも生FileReader結果を
  直接stateに入れないこと。フリーズの原因になる)
- 番号の照合は normNo()(全角→半角、数字抽出、先頭ゼロ除去)で統一すること

## 選択・移動・整列
- 単一選択: クリック。ドラッグで移動(既定50mm刻み=FINE、**Altキーでスナップ無し=1mm自由**)
- 複数選択: Shift/Ctrl/Cmd+クリックでトグル追加、空白を Shift+ドラッグで範囲選択(マーキー、
  中心が矩形内のオブジェクトを追加選択)、Ctrl/Cmd+A で全オブジェクト選択
- 複数選択中はオブジェクトをドラッグするとグループごと移動(主選択を基準にスナップ)
- **壁もオブジェクトと同様にドラッグ移動できる**(始点・終点をまとめて平行移動)。
  壁は state.objects ではなく state.walls にいる別の配列なので、pointerdown の
  ドラッグ対象を組み立てるループは objects・walls の両方を見ること。
  片方だけ見て primary/items を作ると「選択はできるが動かない」不具合になる
  (実際に起きた回帰。tests/fp01_floorplan_smoke.js の壁ドラッグテストで検知)
- **整列ツール**(2個以上選択で右パネルに表示): 左/右/左右中央、上/下/上下中央そろえ、
  横/縦の等間隔配置(disth/distv)。基準は選択全体のバウンディング(壁は対象外、
  state.objects のみ)。当たり判定・整列の寸法は halfExtent()(縮尺fを考慮)で算出
- 選択状態(selectedIds:Set / selectedId:主選択)は保存対象外。履歴のUndoでクリアされる

## 主な機能
- 壁の描画(ドラッグ、直交スナップ / Shiftで自由角度)
- 壁の連結(既存の壁の端点400mm以内に近づけると吸着。連結時は直交スナップより優先)
- Ctrl+Zで元に戻す / Ctrl+Y・Ctrl+Shift+Zでやり直し(履歴50件)。
  ※画像(state.images / rooms.img / objects.img)は履歴スナップショットから除外し、
  Undo/Redoをまたいで現在値を維持する(メモリ対策。snapshot()/applySnapshot()参照)
- タッチ2本指のピンチズーム・パン
- **印刷範囲(A3)は90度きざみで回転できる**(state.sheet.rot: 0/90/180/270、既定0)。
  0°/180°は横向き(42000×29700mm)、90°/270°は縦向き(29700×42000mm)になる
  (矩形なので0°と180°、90°と270°は見た目同じだが、角度の値自体は保持する)。
  ヘッダーの「印刷範囲(A3)の回転」セレクトで切替。normRot()で0/90/180/270に丸める
- **縮尺(0〜150%)**: ケース・展示台の図面に対する表示サイズ倍率(state.scalePct)。
  背景図面の縮尺が不明でも、この%を調整してケースと図面の大きさを合わせる。
  実寸mm(o.w/o.h)は変えず描画時に dispSize()/fsc() を掛けるだけ。
  0%近くでも掴めなくならないよう表示サイズはMIN_DISP(120mm)を下限に保証する
  (halfExtent()・在庫パレット・配置済みオブジェクトすべてdispSize()経由で統一)。
  scalePctは0が正当な値なので `!state.scalePct` のようなfalsy判定は禁止
  (0が100にフォールバックされてしまう。== null で判定すること。過去にこのバグがあった)
- 表題欄は廃止(図面上に展覧会名等は表示しない。state.metaはファイル名用に残存)
- JSON保存/読み込み(旧形式と互換)、PNG書き出し、印刷

## 座標系・単位
- 内部座標はmm。SHEETはA3実寸(mm)×100(state.sheet.rotの0/90/180/270で横縦を切替。
  旧形式JSON(state.sheet.preset: "a3l"/"a3p"等)は読み込み時にrotへ変換する)
- グリッドは500mm、壁厚は固定150mm
- viewBoxで拡縮しているズーム/パン

## 既知の設計上の注意点(SVG特有)
- SVGはCSSがプレゼンテーション属性より優先される。font-size等はCSSクラスに書かず
  属性 or インラインstyleで指定すること(過去に文字が極小になるバグがあった)
- PNG書き出し時、外部<style>はcloneNode後にシリアライズされないため
  書き出し関数内でスタイルをSVGに埋め込んでいる(pngBtnのonclick内)
- render()は呼ばれるたびにsvg.innerHTMLを空にして全要素を再生成する(差分更新ではない)。
  ドラッグ中のpointermoveやスライダーのoninputで毎回呼ばれるため、
  <image>のhrefに巨大なdataURLを入れるとブラウザが毎フレーム再デコードしてフリーズする。
  画像を扱う新機能を足すときは必ずcompressImage()系を経由してdataURLを小さく保つこと
